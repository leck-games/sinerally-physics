# Merge notes: bringing these modules into leck-games/sinerally

This repo is a standalone copy, and nothing here touches the main game repo. Copy `physics/`, `vehicles/`, `attachments/` and `host/rig.js` + `host/bus.js` into the game (for example under `js/`). `host/main.js` is test-page code: use it as a reference and don't copy it as-is.

1. **Replace the car sim.** The game's `js/vehicle.js` physics becomes `createRig({THREE, world, emit})`. Keep the fixed 120 Hz substep loop and call `rig.step(input, 1/120)`. Each frame, copy `rig.state.p/q` onto the visual group from `buildVehicle()` and onto `rig.root` (the attachment mounts), and call `setWheel(i, w.comp, w.steer, w.rot)`.
2. **World adapter.** Wrap `js/world.js` or the terrain module as a worldQuery: `heightAt` (with bridges), `surfaceAt`, `normalAt`, `queryTrees(x,z,r,out)` returning `{id,x,z,r,hp}`, and `damageTree(id,hp,cause)` that writes HP into the chunk tree store and removes the tree at 0 HP. Tree ids must be stable across chunk reloads, for example `chunkX:chunkZ:index`. Destroyed and harvested trees must stay gone, so persist that set. The stub (`world/stub-world.js`) shows the contract, including `onTreeChange` for re-instancing.
3. **Events.** `PH.drainEvents(state, emit)` runs after each step. Route it into the existing `SR.on/off` event API so the sound plugin can subscribe to `tree:hit`, `tree:destroyed`, `engine:hot`, `engine:overheat`, `crash`, `land`, `scrape`, `shift` and `harvester:*`. Each vehicle def has a `sound` id (e.g. `v12-hyper`) for the sound plugin to pick an engine profile. Another worker is building that API, so the event names may need mapping.
4. **Telemetry.** `PH.telemetry(state, SR.telemetry)` fills the same fields as today's `SR.telemetry` and adds `temp overheat limiter damage mass logs capacity`. Add the temp gauge (HUD markup and CSS are in `index.html` / `host/style.css`: `#gauge`, `#needle`, `#tempTxt`, `#tempWarn`).
5. **Car selector and parts.** Use `openSelector` and `renderPicker` from the game's pause/garage menu, and keep the localStorage keys `srp_vehicle` and `srp_attach_<id>` or rename them. `buildVehicle` reuses the low-poly model code from `js/models.js`, so the buggy, truck and quad are the existing models and the hyper and forester are new.
6. **Tree visuals.** The test page tints trees by HP and shows DOM HP labels. In the game, use instance colour on the existing tree InstancedMesh, and add labels only for trees near the car (a max of about 10 keeps iPhone cost low).
7. **Tuning knobs.** `TREE` (curve), `HEAT`, `DEFAULTS.damageK` and per-vehicle `physics` blocks are all plain data.

Compatibility: the default buggy params match the old handling (same tyre model, suspension and gearbox constants). Physics units are SI: metres, seconds and kg, with g = 12.5 m/s² as in the game.

## Update: harvester melt, -10% top speed, ARCADE handling
- **Harvester** now melts trees at any speed (`mode:'melt'`, all HP in one contact, no bounce, no speed loss, no car damage, 1 log per HP up to capacity). The game should skip chip/smash FX for `cause:'harvest'` (vanish instantly, show only `+N LOG`) and use `melts(rig.attach)` from `attachments/index.js` to melt its own collidable scenery (rocks).
- **Top-speed governor:** attachment `mods.topMul` (the harvester has 0.9) caps speed at `topMul × topRef(P, mode, nitro)`, using the measured `vtop`, `arcade.vtop` and `vtopBoost` in each vehicle def. The harvester's 25 km/h limit is gone.
- **Handling modes:** `s.mode` defaults to `'arcade'`. `rig.setMode('arcade'|'normal')` switches at runtime and survives `setVehicle`. Persist the choice in the host (the lab uses `srp_handling`). New events: `drift:start`, `drift:end`.
